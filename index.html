초거대 모델의 탄생 · 분산 학습

How Mesh-TensorFlow Works — 어떤 차원이든 이름을 붙여 나눈다

데이터 병렬은 모든 장치에 모델 전체를 올리고 배치만 나눕니다. 모델이 한 장치에 들어가지 않으면 모델 자체를 잘라야 하는데, 그 방법은 모델마다 새로 설계해야 했습니다. Mesh-TensorFlow는 이 둘을 같은 말로 적습니다. 텐서의 차원마다 이름을 붙이고, 장치들을 여러 축을 가진 격자(메시)로 본 뒤, “어떤 이름의 차원을 어떤 메시 축으로 나눌지”만 정하면 됩니다. 이 페이지는 Noam Shazeer의 발표 「Mesh-TensorFlow: Model Parallelism for Supercomputers」(TF Dev Summit 2019, 15분)의 순서를 따라가고, 수식과 수치는 논문 Shazeer 외, 「Mesh-TensorFlow: Deep Learning for Supercomputers」(NeurIPS 2018)에서 가져옵니다.

이 자료의 축

데이터 병렬은 batch 차원을 나누는 레이아웃 하나일 뿐이고, 어떤 차원이든 이름을 붙여 메시 축에 나누면 같은 SPMD 프로그램이 모델 병렬이 된다 — 통신은 나눈 차원을 더해 없애는 곳에서만 생긴다. 프로그램(수학 모델)은 그대로 두고 레이아웃 한 줄만 바꾸면, 어떤 텐서가 쪼개지고 어떤 텐서가 복제되는지, all-reduce가 어느 연산에서 어느 메시 축을 따라 생기는지가 전부 정해진다.

① 데이터 병렬→② 왜 큰 모델인가→③ 장치 배치→④ SPMD→⑤ 메시와 이름→⑥ b·h·d 나누기→⑦ 2D 메시→⑧ 레이아웃 규칙→⑨ Transformer→⑩ 레이아웃 고르기→⑪ 사용법과 한계

1. 데이터 병렬: 다들 쓰는 이유와 두 개의 벽

발표는 “거의 모든 사람이 신경망을 학습하는 방식”으로 시작합니다. 모든 장치에 모델 전체를 올리고, 학습 배치를 장치 수만큼 작은 덩어리로 나눠 하나씩 맡깁니다. 각 장치가 자기 덩어리로 순전파·역전파를 하고 나면 파라미터 기울기를 모든 장치에 걸쳐 더한 뒤(all-reduce) 각자 같은 갱신을 합니다. 논문 알고리즘 1이 이것입니다.

$$\nabla Q\big(W^{(t)}, b^{(t)}\big)=\sum_{p'\in P}\nabla Q\big(W^{(t)}, b^{(t)}_{p'}\big)\qquad W^{(t+1)}=\mathrm{Update}\big(W^{(t)},\ \nabla Q(W^{(t)}, b^{(t)})\big)$$ 논문 알고리즘 1. 배치 \(b^{(t)}\)를 장치 집합 \(P\)에 나눈 \(b^{(t)}_p\)로 부분 기울기를 구하고(로컬 계산), 그 합을 all-reduce로 구한 뒤 각자 갱신합니다(로컬 계산).

발표자가 꼽은 장점은 세 가지입니다. 어떤 모델 구조에도 쓸 수 있고, 장치 하나가 할 일만 적은 SPMD 코드를 컴파일해 모든 장치에 똑같이 보내므로 컴파일이 빠르고, 모든 장치가 거의 같은 일을 하니 서로 기다리지 않아 활용률이 거의 100%입니다. 통신도 TPU 포드를 비롯한 여러 네트워크에서 빠릅니다.

문제는 하나, “모델 전체가 모든 장치에 들어가야 한다”는 것입니다. 논문 초록은 여기에 두 가지를 더합니다. 지연 시간이 길고, 배치가 작으면 비효율적입니다. 뒤의 것은 논문 표 1에 식으로 나옵니다. 데이터 병렬의 통신/계산 비율은 \(n/b\), 즉 장치당 배치의 역수입니다. 장치를 늘리면서 배치를 같이 키우지 않으면 통신에 묶입니다.

데모 1 · 장치를 늘려도 줄지 않는 것, 점점 나빠지는 것

장치당 메모리는 파라미터 하나에 16바이트(혼합 정밀도 + Adam, How FSDP Works 1절)로 어림했습니다. 활성값은 넣지 않았습니다. 장치 메모리 한계(빨간 점선)는 가정값이니 바꿔 보세요. 오른쪽 그래프의 n/b는 논문 표 1의 데이터 병렬 행이고, 1이 넘으면 장치에 줄 예제가 1개도 안 됩니다.

왼쪽 선은 장치 수를 아무리 늘려도 평평합니다. 데이터 병렬은 계산을 나눌 뿐 모델을 나누지 않기 때문입니다. 5B 모델이면 80GB가 필요하고, 한 장치에 들어가지 않습니다.

다음 질문

모델이 한 장치에 들어가야 한다는 제약을 피하는 가장 쉬운 방법은 모델을 작게 만드는 것입니다. 그런데 왜 굳이 그렇게 큰 모델이 필요할까요?

2. 왜 큰 모델이 필요한가

발표자는 언어 모델링을 예로 듭니다. 기계 번역, 질의응답, 대화, 감성 분석처럼 쓸 곳이 많고, 모델이 클수록 품질이 좋아집니다. 큰 모델일수록 세상에 대해 더 많이 알고 더 잘 이해합니다. 데이터도 충분합니다. 웹 텍스트(Common Crawl 등)를 받으면 수십억~수조 단어가 생깁니다. 큰 모델 하나를 학습해 여러 과제에 미세 조정하는 전이 학습(OpenAI, BERT)도 이 방향을 밀어 줍니다.

발표의 예는 위키피디아로 학습한 Transformer 언어 모델입니다. 에이브러햄 링컨 문서는 학습에 쓰지 않은 검증 세트에 있었습니다. 파라미터 약 1억 개짜리 모델에게 링컨 문서를 지어내게 하면 문법은 대충 맞고 “미국 정치인”이라는 것은 기억하지만, 링컨이 누구였는지 모르고 미국에 총리가 있다고 씁니다. 같은 구조를 50억 개로 키우면 링컨에 대해 훨씬 많은 것을 알아서, 발표자 말로는 “대략 절반은 맞는” 글을 씁니다. 대부분은 여전히 지어낸 이야기지만 모델 크기가 중요하다는 것을 보여 주기엔 충분합니다.

논문에는 같은 실험의 숫자가 표로 있습니다. Billion-Word 벤치마크에서 dff와 헤드 수만 두 배씩 키운 7개 모델의 퍼플렉시티가 35.0에서 24.0으로 내려가고, logits에 0.9를 곱해 평가하면 23.5로 당시 발표된 최고 기록이었습니다(논문 표 2). 번역(WMT14 En-Fr)에서도 BLEU가 41.8에서 43.9로 올라갑니다(표 3). 부록 C에는 각 모델이 “According to Ray Kurzweil …”를 이어 쓴 문장이 있습니다.

데모 2 · 키울수록 좋아진다 (논문 표 2 · 표 3 · 부록 C)

표 2: Transformer 디코더 언어 모델, dmodel = 1024, dk = dv = 256, Billion-Word 단어 퍼플렉시티. 표 3: Transformer 번역 모델, dmodel = 1024, dk = dv = 128. 아래 문장은 부록 C의 무작위 샘플을 그대로 옮겼습니다(모델마다 8개 중 2개).

과제

0.14B 모델의 문장은 그럴듯한 직함 뒤에 아무 말이나 붙입니다. 4.9B 모델은 커즈와일이 『The Singularity is Near』를 썼다는 것을 압니다. 논문의 표현으로 “모든 모델이 대체로 문법적인 문장을 만들지만, 큰 모델일수록 세상 지식을 더 많이 보여 줍니다.”

다음 질문

50억 개짜리 파라미터는 코어 하나에 들어가지 않습니다. 모델 자체를 여러 장치에 나눠야 합니다(모델 병렬). 지금까지는 어떻게 했고, 무엇이 어려웠을까요?

3. 장치 배치로 하는 모델 병렬과 그 어려움

모델 병렬은 모델을 장치들에 나눠 싣는 것입니다. 아주 큰 모델을 학습할 수 있고, 예제 하나의 계산을 여러 장치가 나눠 하니 추론 지연 시간에도 유리합니다. 문제는 효율적인 알고리즘을 설계하기가 까다롭다는 것입니다.

당시 흔한 방법은 장치 배치(device placement)였습니다. “이 연산은 이 장치에, 저 연산은 저 장치에” 하고 하나하나 지정합니다. TensorFlow는 이것을 쉽게 해 주지만, 효율적인 배치를 찾는 것은 여전히 사람 몫이고, 2,000개 코어에 보낼 연산을 전부 만들면 그래프가 거대해집니다. 논문 서론은 이것을 “MIMD 구현은 매우 큰 프로그램을 만들어 컴파일하고 최적화하기 어렵다”고 적습니다.

발표가 드는 예는 Google 신경망 기계 번역(GNMT)입니다. LSTM 8층을 GPU 8대에 한 층씩 나눠 싣고 softmax 층은 다른 곳에 두었습니다. 그냥 두면 한 층이 일하는 동안 나머지 GPU는 놉니다. 모든 GPU를 바쁘게 하려면 “흥미로운 파이프라이닝”이 필요합니다. 동작은 하지만, 발표자 말대로 “제대로 돌게 만드는 데 일이 많이 듭니다.”

데모 3 · LSTM 8층을 GPU 8대에 나눠 싣기

GNMT식 배치를 단순화했습니다. 층 l은 GPU l에, softmax는 9번째 장치에 있습니다. “층마다 끝까지”는 한 층이 문장 전체를 처리한 뒤 다음 층에 넘기는 순서이고, “파이프라이닝”은 토큰 t가 층 l을 지나자마자 층 l+1이 그 토큰을 받는 대각선 순서입니다. 아래 연산 수는 장치 하나 몫이 연산 1,000개라고 했을 때의 어림입니다.

스케줄

파이프라이닝으로 활용률을 끌어올릴 수는 있지만 그것은 이 모델, 이 장치 수에 맞춘 설계입니다. 층 수가 바뀌거나 장치가 512개가 되면 다시 설계해야 하고, 장치마다 다른 일을 시키니 그래프의 연산 수도 장치 수에 비례해 늘어납니다.

장치마다 다른 일을 시키니 설계도 어렵고 프로그램도 커집니다. 데이터 병렬에는 이 문제가 없었습니다. 데이터 병렬의 무엇이 잘 돌아가게 만든 걸까요?

4. 다른 접근: SPMD와 집합 통신

Mesh-TensorFlow는 “완전히 다른 접근”을 택하고, 그 영감을 동기식 데이터 병렬에서 가져옵니다. 세 가지입니다.

  1. 모든 장치가 모든 연산에 참여한다. 연산 하나를 장치 하나에 맡기지 않고, 모든 장치가 그 연산의 자기 몫을 한다.
  2. SPMD(Single Program, Multiple Data): 모든 장치에 같은 프로그램이 돈다. 프로그램 크기가 장치 수와 무관하다.
  3. 장치 사이의 주고받기는 all-reduce 같은 집합 통신으로만 한다.

논문 3절은 데이터 병렬을 이렇게 다시 봅니다. 계산의 모든 텐서와 연산은 “batch” 차원이 있으면 모든 장치에 나뉘고, 없으면 모든 장치에 복제됩니다. 그리고 batch 차원을 더해 없애는 연산만 올바른 결과를 얻기 위해 all-reduce가 더 필요합니다. 데이터 병렬이란 “계산을 batch 차원으로 나누는 것”입니다.

데모 4 · 나뉜 차원을 더할 때만 통신이 생긴다

텐서 x[batch = 8, d = 3]을 batch를 따라 장치들에 나눴습니다(데이터 병렬). 각 장치는 같은 프로그램 reduce_sum을 자기 조각에 돌립니다. 더해 없애는 차원이 나뉜 batch면 부분합만 나오고 all-reduce가 필요하고, 나뉘지 않은 d면 통신 없이 끝납니다. 숫자는 실제로 계산한 값입니다.

장치 수
더해 없앨 차원

파라미터 기울기 \(\partial L/\partial W=\sum_{\text{batch}} x^\top \delta\)가 정확히 이 경우입니다. 그래서 데이터 병렬에서는 순전파에 통신이 없고, 역전파의 파라미터 기울기에서만 all-reduce가 생깁니다. all-reduce는 장치들이 트리나 토러스처럼 연결되어 있으면 대역폭 효율적으로 구현할 수 있고, 걸리는 시간은 조각 하나의 크기를 링크 대역폭으로 나눈 것에 비례합니다(논문 6절, 8.6절).

다음 질문

이 규칙에는 “batch”라는 이름 말고는 데이터 병렬만의 것이 없습니다. batch 대신 다른 차원을 나누면 어떻게 될까요? 그러려면 먼저 차원에 이름이 있어야 하고, 장치들을 여러 축이 있는 격자로 볼 수 있어야 합니다.

5. 메시와 이름 붙은 차원

논문이 가정하는 하드웨어는 같은 종류의 믿을 만한 프로세서들이고, 각자 로컬 메모리를 갖고 서로 잘 연결되어 있습니다(2절). TPU 포드가 그렇습니다. 이 프로세서들을 n차원 배열로 늘어놓은 것을 메시라고 부릅니다.

메시는 이름 붙이기 위한 추상일 뿐 물리 네트워크 모양을 뜻하지 않습니다. 16 × 16 × 2 토러스로 연결된 512코어 TPU를 [16, 16, 2]짜리 3차원 메시로 볼 수도, [32, 16]짜리 2차원 메시로, [512]짜리 1차원 메시로 볼 수도 있습니다. 다만 성능은 물리 배선의 영향을 받습니다. 특히 메시 축 일부로 묶은 그룹 안에서 하는 all-reduce가 중요한데, 그 그룹이 물리적으로 붙어 있으면 매우 효율적입니다.

새로 들어오는 요소는 셋입니다(논문 4절).

  • 텐서의 차원에 이름이 있다. mtf.Dimension("batch", b)처럼 이름과 크기를 함께 적습니다. 그래서 “batch”라는 논리적 차원이 서로 다른 텐서와 연산에서 똑같이 나뉩니다. 한 텐서에 같은 이름의 차원이 두 개 있으면 안 됩니다.
  • 메시의 차원에도 이름이 있다. 예: [("rows", r), ("cols", c)].
  • 전역 계산 레이아웃은 텐서 차원 → 메시 차원의 부분 함수입니다. 데이터 병렬은 [("batch", "all_processors")]입니다.

각 텐서의 레이아웃은 전역 레이아웃을 그 텐서의 차원으로 제한한 것이고, 단사여야 합니다. 한 텐서의 두 차원이 같은 메시 축에 매핑되면 금지입니다. 레이아웃이 비어 있으면 그 텐서는 모든 장치에 통째로 복제됩니다. (텐서 차원, 메시 차원) 쌍마다 장치는 그 텐서 차원을 자기 메시 좌표에 해당하는 띠만큼 잘라 갖습니다. 현재 구현은 텐서 차원 크기가 메시 차원 크기로 나누어떨어져야 합니다(5절).

데모 5 · 물리 장치 8개를 여러 메시로 보기

물리 보드는 2 × 4로 고정입니다. 랭크는 물리 위치의 행 우선 번호이고, 메시 좌표는 랭크를 메시 모양으로 다시 읽은 것입니다. 장치를 누르면 그 장치와 메시 축마다 같은 그룹(그 축으로 all-reduce 할 때 함께 더하는 장치)이 색 테두리로 표시됩니다. [4, 2]로 보면 rows 그룹이 물리 보드에서 떨어져 있는 것을 확인해 보세요.

6. 두 층 MLP를 b · h · d로 나누기

논문 8절의 예제는 신경망 가운데에 있는 완전연결층 두 개입니다. 입력 x와 출력 y는 dio개 유닛, 은닉 h는 dh개 유닛이고, 은닉층에 편향과 ReLU가 있습니다. 발표에서는 dio를 d, dh를 h, 배치 크기를 b라고 부릅니다.

$$y=\mathrm{Relu}(xw+\mathit{bias})\,v\qquad x:[\text{batch},\text{io}],\ \ w:[\text{io},\text{hidden}],\ \ v:[\text{hidden},\text{io}]$$ 논문 식 (1). Mesh-TensorFlow 코드로는 h = mtf.relu(mtf.einsum(x, w, output_shape=[batch, hidden]) + bias), y = mtf.einsum(h, v, output_shape=[batch, io]) 두 줄입니다. 이 코드는 수학 모델만 정의하고, 어떤 레이아웃으로 돌려도 결과는 같습니다.

여기서 einsum은 모든 입력을 차원의 합집합 모양으로 브로드캐스트해 원소별로 곱한 뒤, 출력에 없는 차원을 더해 없애는 연산입니다. 분산 버전은 장치마다 자기 조각으로 einsum을 하고, 더해 없앤 차원이 나뉜 메시 축을 따라 all-reduce합니다(논문 6절). 이 한 문장이 모든 레이아웃의 통신을 결정합니다.

  • b 나누기(8.1절): batch가 있는 x, h, y는 나뉘고, batch가 없는 w, v, bias는 복제됩니다. 순전파에는 통신이 없습니다. 기울기 dw, dv는 batch를 더해 없애므로 all-reduce가 생기고, 장치당 값은 파라미터 수 ≈ 2diodh입니다.
  • h 나누기(8.2절): hidden이 없는 x, y는 복제되고, h와 w, v, bias는 hidden을 따라 나뉩니다. y를 계산할 때 나뉜 hidden을 더해 없애므로 all-reduce가 생기고, 역전파의 dx에서도 같습니다. 장치당 2bdio입니다.
  • d 나누기(발표에서 언급): 나뉘는 텐서와 복제되는 텐서가 뒤바뀌고 통신 위치도 달라집니다. 같은 규칙으로 따지면 xw와 dh에서 io를 더해 없애므로 장치당 2bdh입니다.

데모 6 · 두 층 MLP 실행기 (1차원 메시)

b = 8, dio = 4, dh = 8인 작은 정수 행렬로 순전파와 역전파(손실 ½‖y − t‖²)를 장치마다 실제로 계산합니다. 그림은 논문 부록 A의 배치를 따랐습니다. 곱 C = AB에서 A는 C의 왼쪽, B는 C의 위에 있습니다. 블록의 숫자는 그 조각을 가진 장치이고, 파란 블록이 고른 장치의 몫입니다. 마지막 줄의 “최대 오차”는 장치별 결과를 모아 단일 장치 결과와 비교한 값입니다. 연산 표의 행을 누르면 그 연산의 장치별 계산을 아래에서 볼 수 있습니다.

7. b와 h를 2차원 메시에 동시에: 분할된 all-reduce

r × c 메시에서 batch를 rows에, hidden을 cols에 나눕니다(논문 8.3절).

mesh_shape = [("rows", r), ("cols", c)]
computation_layout = [("batch", "rows"), ("hidden", "cols")]

각 행의 장치들이 배치의 일부를, 각 열의 장치들이 은닉 유닛의 일부를 맡습니다. x는 장치마다 [b/r, dio] 조각을 갖고 같은 행의 장치끼리는 똑같은 조각입니다. h는 batch와 hidden을 둘 다 가지므로 두 축으로 타일링되어 장치마다 [b/r, dh/c]를 갖습니다.

통신은 여러 곳에서 생기지만 메시 전체가 아니라 한 축을 따라서만 합니다. y를 계산할 때 더해 없애는 hidden은 cols 축에 나뉘어 있으니, rows 좌표가 같은 장치끼리(한 행 안에서)만 더하면 됩니다. 반대로 dw, dv는 rows에 나뉜 batch를 더해 없애므로 한 열 안에서만 더합니다. 이것이 분할된(partitioned) all-reduce입니다.

$$\text{장치당 all-reduce 값}=\frac{2\,b\,d_{io}}{r}+\frac{2\,d_{io}\,d_h}{c}$$ 논문 8.3절. 앞 항은 cols 축(y, dx), 뒤 항은 rows 축(dv, dw)의 몫입니다. 3차원 메시 r × c × p에서 io까지 planes에 나누면 모든 행렬이 두 메시 축으로 타일링되고 세 번째 축으로 복제되며, einsum마다 메시 축 하나를 따라 all-reduce가 생깁니다.

8. 레이아웃 = 텐서 차원 → 메시 축: 일반 규칙과 금지 규칙

발표는 일반형을 한 문장으로 말합니다. “모든 텐서 차원에 이름을 주고, 레이아웃을 텐서 차원에서 메시 차원으로 가는 사상으로 정의한다.” 레이아웃이 정해지면 연산마다 할 일이 기계적으로 정해집니다(논문 6절).

쓸 수 없는 레이아웃은 두 종류입니다.

  • 금지(8.5절): 한 텐서의 두 차원이 같은 메시 축에 매핑되는 레이아웃. 1차원 메시에서 [("batch", "all"), ("hidden", "all")]은 h[batch, hidden] 때문에 금지입니다. 크기가 메시 축으로 나누어떨어지지 않아도 지금 구현에서는 쓸 수 없습니다.
  • 비효율(8.4절): 결과는 맞지만 시간도 메모리도 줄지 않는 레이아웃. 빈 레이아웃 []이 극단적인 예입니다. 효율적이려면 비싼 연산이 모든 메시 축에서 나뉘어야 합니다(복제되면 안 됩니다). 경험칙: 비싼 einsum은 메시 축마다 그 축에 나뉜 입력 차원을 하나씩 가져야 합니다.

9. Transformer 레이아웃: vocab · d_ff · heads

논문이 Transformer에 쓴 모델 병렬 레이아웃은 이것입니다(9절).

mesh_shape = [("all", n)]
computation_layout = [("vocab", "all"), ("d_ff", "all"), ("heads", "all")]

어휘 크기, FFN 은닉층 크기, 어텐션 헤드 수를 각각 모든 장치에 나눕니다. 이 레이아웃이 통하는 이유를 논문은 한 문장으로 적습니다. “모델의 모든 비싼 연산이 이 차원들 중 정확히 하나를 갖고, 어떤 텐서도 둘 이상을 갖지 않는다.” 정확히 하나라서 모든 비싼 연산이 나뉘고(비효율 아님), 둘 이상인 텐서가 없어서 금지에 걸리지 않습니다. 두 층 예제의 h 나누기처럼, 이 차원들을 장치 수에 비례해 키우면 장치당 메모리와 통신 부담이 일정하게 유지됩니다. 실제로 저자들은 은닉층과 헤드 수를 키우면서 TPU 클러스터도 키웠고(어휘는 그대로), 비슷한 성능 특성을 확인했습니다.

장치를 더 쓰려면 데이터 병렬과 섞습니다.

mesh_shape = [("rows", r), ("cols", c)]
computation_layout = [("batch", "rows"), ("vocab", "cols"), ("d_ff", "cols"), ("heads", "cols")]

batch를 r에 비례해, 모델 차원을 c에 비례해 키우면 성능이 유지됩니다. 이 레이아웃으로 dff 최대 262,144, 헤드 최대 256개인 모델을 TPUv2 16 × 32 = 512코어에서 학습했고, 가장 큰 모델에서도 계산 효율 50% 이상(최대 11.5 PFLOP/s 중 6 PFLOP/s)을 유지했습니다. Billion-Word 실험의 배치는 256토큰 시퀀스 256개였고, 배치는 크기 16인 메시 축에, 모델 차원은 크기 32인 축에 나눴습니다. 4.9B 모델은 512코어에서 10에폭에 13시간 걸렸습니다(9.1절).

데모 9a · Transformer 레이아웃 판정기

디코더 층 하나의 텐서와 순전파 einsum입니다. 크기는 논문 표 2를 따랐고(dmodel 1,024, dk 256, 배치 256 × 길이 256), 어휘 크기는 논문에 없어 65,536으로 가정했습니다. memory_length는 키·값 쪽 길이로, length와 이름만 다른 같은 크기 차원입니다. 슬라이더로 표 2의 행(dff, heads)을 바꾸면 나누어떨어짐 판정이 바뀝니다.

메시

몇 가지를 눌러 보면 이 레이아웃이 왜 골라졌는지 보입니다. d_model만 나누기는 합법이지만 어텐션 점수(logits)와 가중합(o) einsum에 d_model이 없어서 32대가 같은 어텐션을 반복합니다. d_model·d_ff는 w_1[d_model, d_ff]과 w_2[d_ff, d_model]가, length·memory_length는 logits가 금지 규칙에 걸립니다. 512코어를 1D로 보면 헤드 수(최대 256)를 512로 나눌 수 없습니다. 512코어를 16 × 32 메시로 본 이유 중 하나입니다.

데모 9b · Transformer 레이아웃 계산기 (장치당 파라미터 · 계산 · 통신)

batch → rows, vocab·d_ff·heads → cols 레이아웃입니다. 논문은 층 수와 어휘 크기를 적지 않았는데, 층 6개 + 층 밖 파라미터 6,740만 개(임베딩으로 보고 vocab을 따라 나눔)로 두면 표 2의 일곱 행이 모두 ±0.01B 안에서 맞아 이 값을 썼습니다. 계산은 6 × 파라미터 × 토큰에 어텐션 점수 계산을 더한 어림입니다. 통신은 이 계산기의 셈법입니다. einsum 하나당 all-reduce 하나로 세서, cols 축은 층마다 순전파 2번(어텐션 출력, FFN 출력)과 역전파 4번(q·k·v 투영, FFN 입력), 어휘 쪽 2번을 [b/r, 길이, dmodel] 크기로 더하고, rows 축은 장치가 가진 파라미터 기울기를 한 번 더합니다.

논문 설정(4.9B, 16 × 32)에서 장치당 파라미터는 약 1억 5천만 개입니다. 전체의 1/32이고, fp32 가중치만 치면 0.6GB입니다. 표에서 c를 고정하고 모델을 키우면 장치당 파라미터와 계산이 함께 늘어 통신/계산 비율은 오히려 줄어듭니다. 거꾸로 모델을 고정하고 c를 키우면 비율이 커집니다. “모델 차원을 c에 비례해 키우면 성능이 유지된다”는 말이 이것입니다.

다음 질문

같은 모델, 같은 장치 수에도 쓸 수 있는 레이아웃은 여러 개입니다. 그중 무엇이 좋은지는 어떻게 고를까요?

10. 좋은 레이아웃 고르기: 메시를 1D로 볼까 2D로 볼까

발표자는 솔직하게 말합니다. 좋은 레이아웃을 고르는 일은 “지금으로서는 잘 훈련된 사람”이 해야 합니다. 지켜야 할 것은 세 가지입니다. 비싼 연산은 전부 나뉘어야 하고, 한 텐서의 두 차원을 같은 메시 축에 나눌 수 없고, 어떤 차원을 자르느냐에 따라 통신이 많아지거나 적어집니다. 데이터 병렬이면 배치가 커야 하고, 은닉층을 자르면 은닉층이 커야 합니다.

논문 표 1은 두 층 예제의 레이아웃별 비용을 정리합니다(상수와 저차항 생략).

레이아웃계산 시간통신 시간통신 / 계산장치당 메모리
[]\(bd_{io}d_h\)00\(bd_{io}+bd_h+d_{io}d_h\)
[("batch","all")]\(\frac{bd_{io}d_h}{n}\)\(d_{io}d_h\)\(\frac{n}{b}\)\(\frac{b}{n}d_{io}+\frac{b}{n}d_h+d_{io}d_h\)
[("hidden","all")]\(\frac{bd_{io}d_h}{n}\)\(d_{io}b\)\(\frac{n}{d_h}\)\(bd_{io}+\frac{bd_h}{n}+\frac{d_{io}d_h}{n}\)
[("batch","rows"), ("hidden","cols")]\(\frac{bd_{io}d_h}{rc}\)\(d_{io}\big(\frac{b}{r}+\frac{d_h}{c}\big)\)\(\frac{c}{d_h}+\frac{r}{b}\)\(\frac{b}{r}d_{io}+\frac{b}{r}\frac{d_h}{c}+\frac{d_{io}d_h}{c}\)
+ ("io","planes")\(\frac{bd_{io}d_h}{rcp}\)\(\frac{bd_{io}}{rp}+\frac{bd_h}{rc}+\frac{d_{io}d_h}{pc}\)\(\frac{c}{d_h}+\frac{p}{d_{io}}+\frac{r}{b}\)\(\frac{bd_{io}}{rp}+\frac{bd_h}{rc}+\frac{d_{io}d_h}{pc}\)

통신/계산 열이 핵심입니다. 이 값에 비례해 네트워크에 묶이고, 비례 상수는 하드웨어의 통신·계산 속도 비가 정합니다. 데이터 병렬은 장치당 배치의 역수 n/b, 모델 병렬은 장치당 은닉 유닛 수의 역수 n/dh입니다. 2D 레이아웃의 c/dh + r/b는 장치 수(rc)를 제곱으로 늘려도 배치와 은닉층은 선형으로만 키우면 같은 효율을 유지한다는 뜻이고, 3D는 세제곱입니다(8.6절).

데모 10 · 같은 n대를 [n]으로 볼까 [r, c]로 볼까

표 1의 식을 그대로 계산합니다. 막대는 메시 모양 r × c마다의 통신/계산 비율(batch → rows, hidden → cols)이고, 크기 1인 축의 항은 통신이 없으니 뺐습니다. 왼쪽 끝 1 × n은 순수 모델 병렬, 오른쪽 끝 n × 1은 순수 데이터 병렬(주황), 초록이 가장 좋은 2D입니다. 보라색 점은 장치당 메모리입니다.

b와 dh가 비슷할 때는 r과 c를 비슷하게 나눈 2D가 양 끝보다 훨씬 낫습니다. 비율의 두 항 r/b와 c/dh가 같아지는 곳이 최적이기 때문입니다. 두 항이 같으려면 r : c = b : dh여야 하니, 기본값(b = 16,384, dh = 32,768, 512대)에서는 16 × 32가 가장 좋습니다. 배치를 키우면 최적이 오른쪽(데이터 병렬)으로, 은닉층을 키우면 왼쪽(모델 병렬)으로 밀립니다. 기본값에서 장치당 메모리는 오른쪽 끝이 가장 큽니다. 모든 장치가 파라미터 전체(diodh)를 들고 있기 때문입니다.

부록 B는 같은 이야기를 행렬곱의 반복 공간(i, j, k 세 축의 정육면체)으로 설명합니다. 출력 행렬을 나눠 맡는 “owner computes” 방식은 반복 공간을 1D나 2D로만 자를 수 있지만, Mesh-TensorFlow는 텐서를 복제할 수 있어서 세 축을 모두 자르는 3D 분할도 표현합니다. u = v = w, 장치 64대일 때 계산/통신 비율이 2D 분할은 2u/17 ≈ 0.12u, 3D 분할은 u/6 ≈ 0.17u입니다. 정육면체에 가까울수록 표면(통신) 대비 부피(계산)가 큽니다.

11. 사용법 · 결과 · 한계

사용법은 네 단계입니다(발표, 논문 7절). 오픈소스 저장소(github.com/tensorflow/mesh)를 받고, 보통의 TensorFlow 그래프처럼 Python으로 그래프를 짜되 이름 붙은 차원을 쓰고, 메시와 그것이 물리 프로세서에 어떻게 대응하는지 정하고, 레이아웃을 정합니다. 그러면 Mesh-TensorFlow가 그 그래프를 TensorFlow 그래프의 일부로 “내려(lower)” 줍니다. 데이터 파이프라인처럼 나머지는 그대로 TensorFlow로 합니다.

데모 11 · 분산 방법을 바꿔도 바뀌는 건 두 줄

논문 8절의 코드 조각입니다. 위쪽 수학 모델은 그대로이고, 아래 두 줄만 바뀝니다. 표는 그 두 줄로 정해지는 장치당 조각 모양입니다(굵은 숫자가 나뉜 차원).


  





결과. 최대 50억 파라미터 Transformer를 TPU 포드 전체(512코어)에서 좋은 성능으로 학습했고, 언어 모델링(Billion-Word 퍼플렉시티 23.5)과 기계 번역(WMT14 En-Fr BLEU 43.9, 128코어에서 22시간)에서 당시 최고 기록을 냈습니다(논문 9.1절). 발표 시점에는 수천억 파라미터까지 “돌아가는 것”은 확인했고, 적절한 희소성을 넣으면 1조 파라미터도 학습할 계산량이 된다고 봤습니다.


한계. SPMD 코드는 TPU(Cloud TPU 포함)용만 있었고, CPU·GPU에서는 예전 방식인 장치 배치(MIMD) 코드를 만들어서 돌기는 하지만 확장성이 떨어졌습니다. TensorFlow 1에서만 돌았습니다. 가장 큰 한계는 레이아웃을 사람이 골라야 한다는 점입니다. 논문의 향후 과제도 최적 레이아웃 자동 탐색, 공간으로 나눈 합성곱에 필요한 halo 영역 통신 같은 연산 추가, CPU/GPU 클러스터용 SPMD입니다.


이름 붙은 차원과 메시라는 생각은 이후 GSPMD, JAX의 PartitionSpec, PyTorch의 DeviceMesh/DTensor로 이어졌습니다. 같은 시리즈의 How Parallelism Works 5절은 Mesh-TensorFlow 레이아웃을 데이터·텐서·파이프라인·컨텍스트·전문가 병렬 사이에 놓고 짧게 다루고, 9절에서 Llama 3 405B의 4D 병렬화를 [TP, CP, PP, DP] 네 축짜리 메시로 봅니다. 4절의 Megatron-LM 텐서 병렬(MLP의 A를 열로, B를 행으로 자르고 끝에 all-reduce)은 이 페이지의 h 나누기와 같은 레이아웃입니다. 데이터 병렬의 메모리 문제를 다른 방향(저장만 나누기)에서 푸는 How FSDP Works, 층으로 자르는 How GPipe Works도 함께 보면 좋습니다.
